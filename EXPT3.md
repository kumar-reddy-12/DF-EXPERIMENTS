# Experiment 3: Password Capturing Using Wireshark

## Aim

To demonstrate how login credentials can be exposed in **unencrypted HTTP network traffic** using Wireshark in an authorized laboratory environment.

## Software Used

* Wireshark
* Windows/Linux
* Web Browser
* Test Web Server or Lab Website

## Introduction

Wireshark is a network protocol analyzer used to capture and inspect network packets transmitted between devices.

When information is transmitted using an **unencrypted protocol such as HTTP**, sensitive information such as usernames and passwords may be visible within the captured network traffic.

Wireshark can capture different types of network information, including:

* HTTP requests
* FTP traffic
* Telnet traffic
* Usernames
* Form data
* Other unencrypted network information

This experiment demonstrates the security risk of transmitting login credentials over unencrypted HTTP. The demonstration should be performed only with a test account and an authorized lab network.

## Procedure

### Step 1: Open Wireshark

Open **Wireshark** on the Windows system or Linux virtual machine.

Select the appropriate network interface, such as the wireless network interface, and start packet capture.

---

### Step 2: Generate Test Login Traffic

Open the authorized **test website** in a web browser.

Enter the test login credentials provided for the laboratory exercise.

Submit the login form.

The browser generates network packets containing the HTTP request.

---

### Step 3: Stop Packet Capture

After submitting the test login form, return to Wireshark.

Stop the packet capture.

The captured packets can now be examined to identify the HTTP request generated by the test login.

---

### Step 4: Filter HTTP Packets

Wireshark captures many types of network packets.

To display only HTTP traffic, enter the following display filter in the Wireshark filter bar:

```text
http
```

Press **Enter**.

Wireshark displays the captured HTTP packets.

---

### Step 5: Identify Login Request

HTTP commonly uses request methods such as:

* **GET** – Used to request information from a server.
* **POST** – Commonly used to submit form data to a server.

The captured HTTP packets are examined to identify the request associated with the test login.

---

### Step 6: Check GET Requests

To display HTTP GET requests, use the following Wireshark display filter:

```text
http.request.method == "GET"
```

The GET requests can be examined to determine whether any login information was included in the request.

In a typical login form, the credentials may instead be submitted through a POST request.

---

### Step 7: Check POST Requests

To identify HTTP POST requests, use:

```text
http.request.method == "POST"
```

Wireshark displays the captured POST requests.

Select the relevant **authorized test request** and inspect its packet details.

---

### Step 8: Examine Form Data

If the test website sends the login form using unencrypted HTTP, the submitted form data may be visible in the packet contents.

The HTTP request details can be expanded to examine the request and its form data.

For the laboratory demonstration, the test credentials can be represented as:

```text
Username: TEST_USER
Password: TEST_PASSWORD
```

The important observation is that **unencrypted HTTP can expose submitted form information to someone who can capture the traffic**.

---

### Step 9: Security Observation

The experiment demonstrates why transmitting passwords over HTTP is insecure.

If authentication information is transmitted without encryption, an attacker capable of monitoring the network may be able to inspect the traffic.

Modern websites should therefore use:

**HTTPS instead of HTTP**

HTTPS encrypts the communication between the browser and the web server, making the transmitted credentials substantially harder to obtain through ordinary packet inspection.

## Observation

| Parameter          | Result                      |
| ------------------ | --------------------------- |
| Tool Used          | Wireshark                   |
| Traffic Captured   | Network Traffic             |
| Protocol Examined  | HTTP                        |
| Request Methods    | GET / POST                  |
| Test Login         | Successfully Captured       |
| Form Data          | Visible in Unencrypted HTTP |
| Password Exposure  | Possible over HTTP          |
| Secure Alternative | HTTPS                       |

## Result

The network traffic generated by an authorized test login was successfully captured and analyzed using **Wireshark**.

The experiment demonstrated that login information transmitted through **unencrypted HTTP** may be exposed in captured network packets.
